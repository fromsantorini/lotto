# LSTM 조합 점수 추천 모델 설계

## 목표

현재의 번호별 독립 확률 상위 선택과 확률 가중 샘플링을 제거하고, 과거 회차 흐름과 후보 6개 번호를 함께 입력받아 조합 전체를 평가하는 모델로 교체한다. 추천 결과는 LSTM의 시계열 표현을 사용하면서 기존 통계 균형 조건을 만족해야 한다.

이 기능은 로또 당첨 확률 향상을 보장하지 않는다. 모델 점수는 후보 간 상대 비교값이며 당첨 확률로 표시하지 않는다.

## 범위

- `tools/train-lstm-lotto.py`의 학습 모델과 추천 생성 로직 변경
- `lstm-prediction.json` 출력 형식 변경
- `index.html`의 딥러닝 추천 설명과 렌더링 변경
- 자체 점검과 시간순 검증 지표 추가

기존 데이터 갱신, 예측 이력 누적, 통계 추천 3세트, GitHub Actions 실행 구조는 유지한다.

## 모델 구조

모델은 두 입력을 받는다.

1. 직전 10회차를 나타내는 `(10, 45)` 멀티핫 시퀀스
2. 평가할 후보 6개를 나타내는 `(45,)` 멀티핫 벡터

시퀀스는 기존과 같이 `LSTM(128)`로 인코딩한다. 인코딩 결과와 후보 벡터를 연결한 뒤 `Dense(64, relu)`와 `Dense(1, sigmoid)`를 거쳐 단일 조합 점수를 출력한다.

```text
과거 10회 (10x45) -> LSTM(128) ----+
                                      +-> Dense -> 조합 점수
후보 조합 (45 멀티핫) ---------------+
```

출력 점수는 후보 조합의 상대 순위를 정하는 용도로만 사용한다.

## 학습 데이터

각 회차의 직전 10회 시퀀스와 실제 다음 회차 번호를 양성 예제로 만든다. 단, 추천 시 평가하는 후보 영역과 학습 영역을 일치시키기 위해 아래 균형 조건을 만족하는 실제 조합만 양성 예제로 사용한다. 각 양성 예제마다 같은 시점에 사용할 수 있는 정보만으로 음성 후보 5개를 생성한다.

음성 후보도 다음 균형 조건을 만족해야 한다.

- 홀짝 비율 2:4에서 4:2
- 1~22와 23~45 비율 2:4에서 4:2
- 번호 합계 90~180
- 같은 끝수 최대 2개
- 3개 이상 연속 번호 제외
- 해당 양성 조합과 불일치

양성과 음성 모두 같은 균형 조건을 적용해 모델이 `불균형 조합 = 실제 당첨 조합` 같은 지름길을 배우지 않고 과거 시퀀스와 후보 조합의 관계를 학습하도록 한다.

학습과 검증은 회차 순서를 유지해 분리한다. 미래 회차 정보는 이전 회차의 음성 후보 생성이나 학습에 사용하지 않는다. 검증 지표는 후보 점수의 ROC AUC를 기록한다.

## 추천 생성

다음 회차 추천 시 고정 시드로 균형 조건을 만족하는 후보 50,000개를 만든다. 중복 후보와 역대 1등 당첨 조합을 제거한 뒤 모델이 후보를 배치 단위로 평가한다.

추천 두 세트는 다음 기준으로 선택한다.

1. `lstm-combination-best`: 전체 후보 중 모델 점수가 가장 높은 조합
2. `lstm-combination-diverse`: 첫 조합과 겹치는 번호가 2개 이하인 후보 중 점수가 가장 높은 조합

후보가 두 세트 미만이면 잘못된 결과를 게시하지 않고 학습 작업을 실패시킨다.

후보 50,000개는 CI 실행 비용을 제한하기 위한 상한이다. 과거 검증에서 후보 수에 따라 결과가 불안정하면 배치 평가를 유지한 채 후보 수를 늘린다.

## 출력 형식

`lstm-prediction.json`은 개별 번호 확률인 `topNumbers`를 제거하고 다음 정보를 기록한다. 아래 예시는 변경되는 딥러닝 추천 두 세트만 보여준다. 실제 `recommendations` 배열에는 기존 `balanced-statistical` 추천 세 세트가 뒤이어 포함되어 총 다섯 세트를 유지한다. `trainSampleCount`는 음성 후보로 확장하기 전의 양성 시퀀스 개수다.

```json
{
  "schemaVersion": 2,
  "model": "keras-lstm-combination-scorer-v1",
  "sourceLatestRound": 1233,
  "targetRound": 1234,
  "trainedAt": "2026-07-18T19:22:17Z",
  "window": 10,
  "epochs": 10,
  "trainSampleCount": 1223,
  "validationAuc": 0.51,
  "candidateCount": 50000,
  "recommendations": [
    {
      "method": "lstm-combination-best",
      "numbers": [3, 8, 14, 22, 31, 40],
      "modelScore": 0.73
    },
    {
      "method": "lstm-combination-diverse",
      "numbers": [5, 11, 19, 27, 34, 42],
      "modelScore": 0.69
    }
  ],
  "warning": "모델 점수는 후보 간 상대 비교값이며 당첨 확률이 아닙니다."
}
```

`modelScore`는 화면에서 소수 점수로 표시하며 백분율이나 당첨 확률이라는 표현을 사용하지 않는다.

## 화면 변경

기존 `LSTM 상위 확률`과 `LSTM 확률 가중 샘플` 카드를 제거한다. 새 추천은 `LSTM 최고 점수 조합`과 `LSTM 다양성 조합`으로 표시한다.

딥러닝 영역에는 다음 정보를 함께 표시한다.

- 대상 회차와 학습 시각
- 조합의 상대 모델 점수
- 시간순 검증 AUC
- 모델 점수가 당첨 확률이 아니라는 경고

JSON이 없거나 스키마가 잘못됐거나 최신 회차와 맞지 않으면 기존처럼 딥러닝 영역만 비활성화하고 통계 추천과 다른 화면은 정상 동작한다.

## 예측 이력

기존 이력 구조와 실제 당첨번호 대조 로직을 유지한다. 새 `method` 값과 `modelScore`를 추천 항목에 그대로 보존한다. 과거 schema version 1 이력도 읽을 수 있도록 이력 파일의 최상위 스키마는 변경하지 않는다.

## 검증

가벼운 자체 점검은 다음을 확인한다.

- 음성 후보가 1~45 범위의 중복 없는 6개인지
- 모든 후보가 균형 조건을 만족하는지
- 같은 시드에서 후보와 최종 추천이 동일한지
- 두 추천 조합의 중복 번호가 2개 이하인지
- 역대 당첨 조합이 추천에서 제외되는지
- 출력 JSON이 schema version 2 요구사항을 만족하는지

모델 평가는 마지막 구간을 시간순 검증 데이터로 남기고 AUC를 기록한다. 추가로 과거 회차를 순차 재현해 기존 상위 확률, 가중 샘플, 새 조합 점수 모델의 평균 적중 개수와 3개 이상 적중 빈도를 비교한다. 검증 성능이 무작위 수준이어도 결과를 숨기지 않고 AUC와 실험 경고를 함께 표시한다.

## 완료 기준

- CI 재학습이 schema version 2 예측 파일을 생성한다.
- 딥러닝 추천 두 세트가 모든 균형 및 중복 제한을 만족한다.
- 동일 입력과 시드에서 동일한 추천이 생성된다.
- 화면에 개별 번호 확률이 남지 않는다.
- 화면과 예측 이력에서 새 조합 추천과 모델 점수를 확인할 수 있다.
- 통계 추천 3세트와 기존 데이터 갱신 흐름이 유지된다.
